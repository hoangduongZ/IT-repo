Feynman Method Spring Boot MCP HTTP / JSON-RPC

Spring Boot nhận gì và trả gì khi chạy MCP?

Mục tiêu: sau trang này bạn có thể tự giải thích MCP cho người khác chỉ bằng một câu: HTTP là đường vận chuyển, MCP là luật đóng gói/giao tiếp, Spring Boot là server thực thi tool.

1. Bắt đầu từ thứ bạn đã biết: REST

HTTP

Con đường vận chuyển request/response.

REST

Quy ước bạn thiết kế endpoint + payload business.

MCP

Protocol để client/AI khám phá và gọi capability/tool.

🚚

Ẩn dụ xe tải

HTTP = xe tải. Xe tải không quan tâm nó chở REST hay MCP.

Body = kiện hàng. REST và MCP đóng kiện theo hai quy tắc khác nhau.

Nhớ câu này

REST: “Tôi muốn tạo đơn hàng này.”
MCP: “Hãy gọi tool get_order với id=1001.”

2. Cùng là HTTP, nhưng payload khác nhau

REST request

Business payload do API của bạn định nghĩa.

POST /api/orders
Content-Type: application/json

{
  "productId": 10,
  "quantity": 2
}

Spring MVC thường map body → DTO → Controller.

MCP request

Protocol message, thường dùng JSON-RPC 2.0.

POST /mcp
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 123,
  "method": "tools/call",
  "params": {
    "name": "get_order",
    "arguments": {
      "id": 1001
    }
  }
}

Spring AI MCP layer đọc protocol → tìm tool → gọi Java method.

5. Spring Boot code nhìn như thế nào?

@Component
class OrderMcpTools {

    private final OrderService orderService;

    OrderMcpTools(OrderService orderService) {
        this.orderService = orderService;
    }

    @McpTool(
        name = "get_order",
        description = "Get order information"
    )
    Order getOrder(Long id) {
        return orderService.getOrder(id);
    }
}
@RestController
@RequestMapping("/api/orders")
class OrderController {

    private final OrderService orderService;

    @GetMapping("/{id}")
    Order getOrder(@PathVariable Long id) {
        return orderService.getOrder(id);
    }
}
@Service
class OrderService {

    Order getOrder(Long id) {
        // query DB, validate, apply business rules...
        return repository.findById(id)
            .orElseThrow();
    }
}
Điểm kiến trúc quan trọng: REST Controller và MCP Tool đều chỉ là inbound adapter. Business logic vẫn nằm trong Service/Domain. Không nên copy business logic sang MCP layer.

7. Điều rất dễ hiểu sai

❌ MCP không phải AI

MCP không “suy nghĩ”. Nó chỉ chuẩn hóa cách client và server mô tả / gọi capability.

❌ HTTP không đồng nghĩa REST

HTTP là transport. REST có thể chạy trên HTTP; MCP Streamable HTTP cũng chạy trên HTTP.

❌ Không cần tự viết POST /mcp

Khi dùng Spring AI MCP starter, infrastructure có thể expose endpoint và xử lý protocol cho bạn.

❌ AI không gọi thẳng DB

Thiết kế tốt là AI → MCP tool → Application/Service → DB. Tool là cửa vào được kiểm soát.

9. Tự kiểm tra kiểu Feynman

Q1. MCP chạy qua HTTP thì MCP có phải REST không?
Không. HTTP là transport. REST và MCP là hai cách giao tiếp khác nhau có thể cùng dùng HTTP.
Q2. Ai quyết định gọi get_order?
Agent/model phía client quyết định dựa trên tool metadata. MCP chỉ cung cấp cơ chế discovery và invocation.
Q3. Business logic nên nằm trong @McpTool không?
Không nên. MCP Tool nên mỏng và gọi Service/Application layer, giống Controller.
Q4. Spring Boot MCP Server có tự “nói tiếng người” với user không?
Không nhất thiết. Server trả tool result; AI/agent thường là bên diễn giải kết quả thành câu trả lời tự nhiên.

10. Một câu kết để nhớ lâu

MCP = ổ cắm chuẩn cho AI

Spring Boot của bạn có “thiết bị” là các capability/business function. @McpTool biến capability thành đầu cắm chuẩn; MCP client biết cách cắm vào; còn AI quyết định lúc nào cần sử dụng nó.
